# Переход на Ubuntu Server и Ansible — 2026-10-23

Владелец выбрал обычный Ubuntu Server вместо NixOS и Ansible для настройки.
Foundation реализован локально; deployment, Ubuntu VM и live checks не выполнялись.
Нормативные требования находятся в [specs](../README.md), этот документ фиксирует
источник, границы переиспользования и состояние перехода.

## Решение и сохранённые требования

- VPS создаётся с Ubuntu в панели провайдера. Ansible настраивает установленную
  ОС по SSH; переустановка через nixos-anywhere и разметка disko исключены.
- Версия Ubuntu и совместимые версии Ansible/collections выбираются и проверяются
  при реализации. Конкретный релиз этим решением не закреплён.
- Обновления пакетов и конфигурации ручные, reboot ручной. Nix generations и
  атомарный откат ОС больше не являются моделью эксплуатации. Повторное применение
  playbook и поддерживаемое восстановление конфигурации не возвращают старый доступ.
- Сохраняются admin-only SSH с проверкой host key, повышение через `su`, обе VPN
  на TCP/UDP 443, IPv4/IPv6, изоляция пиров, локальная выдача и отзыв, Make-интерфейс,
  уведомления и остальные требования, не зависящие от платформы.
- SOPS/age, независимые owner/VPS recipients и owner-only CA/client state
  сохраняются. Ansible управляет доставкой ciphertext и runtime-дешифрованием
  вместо sops-nix. Использование Ansible Vault в источнике само по себе не
  меняет согласованную схему хранения Bastion.
- Владелец разрешил копировать необходимые секреты из старого проекта. В рамках
  документационной работы они не копировались и не расшифровывались.

## Проверенный локальный источник

Изучен `/home/alejandro/go/src/ansible`; файлы источника не изменялись.
Это наблюдения о локальных файлах, не о работающем сервере и не проверка
актуальности удалённых upstream-репозиториев.

| Источник | Что использовать / адаптировать |
| --- | --- |
| `playbook.yml`, `Makefile` | Разделение настройки, обновления и локальных команд. VPN-role в основном playbook закомментирована; наличие роли не доказывает её развёртывание. |
| `roles/user`, `roles/ssh` | Создание admin, пароли admin/root и SSH public key. Согласовать последующие подключения через admin + su, проверить действующий sshd config и повторное применение без смены password hash. |
| `ansible.cfg` | Не переносить `host_key_checking = False`, тестовый inventory по умолчанию и незащищённое логирование секретных задач. |
| `roles/ssh_keys` | Не переносить восстановление приватного SSH-ключа через seed на VPS. |
| `roles/vpns`, `roles/gen_vpn` | Использовать только как историческое описание операций. Не переносить интерактивные download-and-run installers, серверную выдачу клиентских ключей и скачивание private profiles с VPS. |
| `roles/ufw` | Переписать под SSH, OpenVPN TCP/443, WireGuard UDP/443, обе IP-семьи и изоляцию. Не переносить открытый TCP/80 или OpenVPN UDP из старой роли. |
| `roles/fail2ban`, `src/fail2ban/jail.local` | Использовать для понимания подключения логов; старые maxretry/bantime/findtime overrides противоречат требованию использовать defaults выбранного пакета. |
| `roles/ssh_notify` | Сохранить интеграцию с тем же приложением; закрепить revision/artifact, передавать полную конфигурацию через защищённый файл. Не переносить токен в Make/command arguments. |
| `roles/update_vpn` | Заменить безусловный reboot ручным и обеспечить persistent networking; не восстанавливать IPv4 NAT разовыми командами после каждой загрузки. |
| `secret`, локальный `vault.txt` | Наличие Vault ciphertext и файла пароля подтверждено без вывода содержимого. При реализации перенести только нужные значения в SOPS/age; пароль Vault остаётся локальным вне Git. |

Docker, shell customization и прочие инструменты старого playbook не становятся
требованиями Bastion. Импорт секретов не означает перенос старого VPN-доступа:
новая OpenVPN server identity и локальность CA/client keys остаются обязательными.

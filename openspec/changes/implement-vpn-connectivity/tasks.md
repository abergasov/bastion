Проверка: ссылка на использованную upstream-документацию и план измерения throughput/CPU для 1 vCPU добавлены рядом с конфигурацией. Требование: [VPN transports](../../specs/vpn-connectivity/spec.md#requirement-vpn-transports), [OpenVPN performance priority](../../specs/vpn-connectivity/spec.md#requirement-openvpn-performance-priority).
- [ ] 1.2 Создать NixOS-модули/параметры для IP-конечных точек OpenVPN TCP/443 и WireGuard UDP/443, получающие только server private keys из защищённых SOPS/sops-nix runtime-файлов. Проверка: evaluation подтверждает отсутствие секретов в store и protocol-compatible test peers завершают handshake на обоих listener. Требование: [VPN transports](../../specs/vpn-connectivity/spec.md#requirement-vpn-transports), [Encrypted server VPN keys in Git](../../specs/recovery-and-verification/spec.md#requirement-encrypted-server-vpn-keys-in-git).
- [ ] 1.3 Задокументировать и реализовать серверный consumer root-only `/var/lib/bastion/vpn`: отдельные WireGuard public key/address и OpenVPN CA/certificate/CRL/public metadata inputs, атомарное чтение завершённого состояния и server-side apply/verify hooks. Проверка: evaluation и fixture подтверждают, что нет static membership list в Nix store/system generations, CA private key и client private keys отсутствуют на VPS. Требование: [Local credential issuance and public server state](../../specs/device-lifecycle/spec.md#requirement-local-credential-issuance-and-public-server-state), [Authenticated and consistent mutations](../../specs/device-lifecycle/spec.md#requirement-authenticated-and-consistent-mutations).

## 2. Сетевая связность и изоляция

- [ ] 2.1 Настроить непересекающиеся IPv4/IPv6 tunnel pools, kernel forwarding и egress/NAT либо эквивалентную маршрутизацию для обоих протоколов через фактические публичные интерфейсы VPS. Проверка: NixOS test peer передаёт IPv4 и IPv6 трафик через каждый туннель, а controlled dual-stack peer использует IPv6 и сохраняет IPv4 fallback. Требование: [Server-side full-tunnel support and DNS settings](../../specs/vpn-connectivity/spec.md#requirement-server-side-full-tunnel-support-and-dns-settings), [Prefer IPv6 for outbound connections](../../specs/vpn-connectivity/spec.md#requirement-prefer-ipv6-for-outbound-connections).
- [ ] 2.2 Добавить firewall для IPv4 и IPv6: разрешить только SSH, TCP/443 OpenVPN, UDP/443 WireGuard, established/related и требуемый control traffic; не вводить egress denylist, destination/port restrictions или private/metadata исключения. Проверка: NixOS test проверяет разрешённые listener, отклонение иных новых входящих соединений и успешный неограниченный tunnel egress к test destinations. Требование: [Inbound services and unrestricted outbound traffic](../../specs/vpn-connectivity/spec.md#requirement-inbound-services-and-unrestricted-outbound-traffic), [Public key-only SSH](../../specs/server-administration/spec.md#requirement-public-key-only-ssh).
- [ ] 2.3 Добавить правила forwarding, которые до разрешения tunnel→internet блокируют IPv4 и IPv6 между WireGuard peers, между OpenVPN peers и между протоколами, включая устройства одного владельца. Проверка: NixOS test выполняет матрицу WG↔WG, OpenVPN↔OpenVPN и WG↔OpenVPN для обеих IP-семей и фиксирует отказ каждой межклиентской попытки при доступном внешнем egress. Требование: [Server-side client isolation](../../specs/vpn-connectivity/spec.md#requirement-server-side-client-isolation).
- [ ] 2.4 Рекламировать full-tunnel routes и DNS `1.1.1.1`, затем `8.8.8.8` в применимых OpenVPN/WireGuard settings, не добавляя DNS service/forwarder. Проверка: configuration test проверяет порядок advertised settings и отсутствие локального DNS-процесса, а NixOS fixture подтверждает пересылку DNS-пакетов через оба туннеля; проверка обоих публичных резолверов внесена в checklist change 6. Требование: [Server-side full-tunnel support and DNS settings](../../specs/vpn-connectivity/spec.md#requirement-server-side-full-tunnel-support-and-dns-settings).

- [ ] 3.1 Добавить test-only public fixtures в контракт `/var/lib/bastion/vpn`, не реализуя management CLI, выдачу или экспорт. Проверка: server-side fixture содержит только допустимые public enrollment data; synthetic test private material остаётся только у test peers и не попадает на VPS, в `/var/lib/bastion/vpn` или Make targets. Требование: [User-owned applications and device configuration](../../specs/vpn-connectivity/spec.md#requirement-user-owned-applications-and-device-configuration), [Local credential issuance and public server state](../../specs/device-lifecycle/spec.md#requirement-local-credential-issuance-and-public-server-state).
- [ ] 3.2 Проверить server-side consumer public-state contract независимо от lifecycle: fixture атомарно заменяет полное состояние и вызывает apply/verify hook, а неполное или недопустимое состояние отклоняется без сообщения об успехе. Проверка: NixOS integration test показывает применение полной fixture и отказ неполной/недопустимой fixture; VPN-конфигурация не содержит второго membership state. Требование: [Authenticated and consistent mutations](../../specs/device-lifecycle/spec.md#requirement-authenticated-and-consistent-mutations), [Revocations survive system lifecycle operations](../../specs/device-lifecycle/spec.md#requirement-revocations-survive-system-lifecycle-operations).

Проверка: сфокусированный NixOS test покрывает читаемый и missing/unreadable/invalid/expired CRL, а integration report явно фиксирует наблюдаемое admission behavior. Требование: [Effective OpenVPN revocation](../../specs/device-lifecycle/spec.md#requirement-effective-openvpn-revocation).
- [ ] 3.4 Запустить formatter/static checks, `nix flake check`, build selected host closure и все добавленные NixOS tests; записать результаты, исключения и отсутствие выполненных live checks. Проверка: команды завершаются успешно либо failure/unrun status документирован без заявления о готовности. Требование: [Build and integration verification](../../specs/recovery-and-verification/spec.md#requirement-build-and-integration-verification).

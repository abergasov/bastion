Связано с Requirement: Local credential issuance and public server state.
- [ ] 1.2 До выбора PKI и runtime-команд перепроверить по актуальной первичной документации поддерживаемых Ubuntu, Ansible, OpenVPN и WireGuard способ создания локальных certificate/CRL и применения public-state; записать выбранные версии и команды рядом с реализацией и подтвердить их focused synthetic-key test. Связано с Requirement: Effective OpenVPN revocation и Requirement: Effective WireGuard revocation.
- [ ] 1.3 Определить компактную versioned схему локального authority state, ciphertext path, Git-ignore rules, owner-only working directory и точные protocol-пути/форматы tree `/var/lib/bastion/vpn`; проверить round-trip synthetic state и отсутствие plaintext/профилей в Git status. Связано с Requirement: Local credential issuance and public server state и Requirement: Private profile handling.

## 2. Реализовать локальную authority и выдачу

- [ ] 2.1 Реализовать owner-only local state и atomic age save для единственного owner recipient, с простым advisory lock; проверить permissions, decrypt/reload round trip, reject VPS recipient и отсутствие private age key, CA/client key в репозитории, логах и command arguments. Связано с Requirement: Local credential issuance and public server state и recovery-and-verification / Requirement: Owner-only age encryption of local credential state.
- [ ] 2.2 Реализовать локальную initial/replacement выдачу OpenVPN CA, OpenVPN/WireGuard server keypairs, OpenVPN client certificate/key, CRL и WireGuard device keypair с issuance/serial/revocation records; передавать server private keys только в SOPS/age поток, а CA/client private material не включать в VPS deployment. Проверить это на synthetic keys и проверить, что duplicate issuance не перезаписывает существующий private key. Связано с Requirement: Local credential issuance and public server state и Requirement: Validate inputs before mutation.
- [ ] 2.3 Реализовать проверку canonical device name, public key, address, duplicate и path до любой записи или shell/SSH invocation; покрыть invalid/unsafe/duplicate inputs focused tests, подтверждающими отсутствие mutation и remote call. Связано с Requirement: Validate inputs before mutation.
- [ ] 2.4 Реализовать local-only экспорт `.conf` и `.ovpn` с restrictive permissions и Git-ignore; producer обоих профилей берёт current endpoint из общего VPN contract и записывает full-tunnel IPv4/IPv6 routes, DNS `1.1.1.1` затем `8.8.8.8` (в WireGuard profile, поскольку сервер не может push DNS). Покрыть export текущего OpenVPN `peer-fingerprint`, missing current server certificate, missing local private key и удаление export file без изменения revocation record. Связано с Requirement: Private profile handling, vpn-connectivity / Requirement: OpenVPN profile server fingerprint и Requirement: Server-side full-tunnel support and DNS settings.

## 3. Публиковать и применять public-state

- [ ] 3.1 Реализовать staged, atomic root-only publish public-state в `/var/lib/bastion/vpn` по SSH как `admin` с host-key verification и интерактивным `su` к root, без передачи паролей, токенов или private keys в аргументах; проверить remote fixture, file ownership/modes и inspect всех VPS/SOPS-readable files на отсутствие CA/client private keys. Связано с Requirement: Authenticated and consistent mutations и recovery-and-verification / Requirement: Encrypted server VPN keys in Git.
- [ ] 3.2 Подключить новый public-state к hooks `implement-vpn-connectivity`: WireGuard применяет тот же peer set к persistent source и running interface, OpenVPN читает CA/cert/CRL; проверить fixture contract, что Ansible configuration не содержит второго membership list. Связано с Requirement: Local credential issuance and public server state и Requirement: Effective WireGuard revocation.
- [ ] 3.3 Реализовать общий locked add/revoke transaction: validate, stage, atomic local ciphertext save, publish, apply/reload и verification; при каждом сбое вернуть clear partial-failure result, не объявлять success и сделать reconciliation/retry idempotent. Покрыть failures до ciphertext, после ciphertext, во время transfer, apply и verification без lost update или partially written state. Связано с Requirement: Authenticated and consistent mutations.
- [ ] 3.4 Реализовать WireGuard revoke как удаление peer из public persistent source и live interface; проверить immediate denial и отсутствие peer после service restart, reboot и Ansible rerun. Связано с Requirement: Effective WireGuard revocation и Requirement: Revocations survive system lifecycle operations.
- [ ] 3.5 Реализовать OpenVPN revoke как локальную запись, новый locally signed CRL, atomic publish и краткий restart OpenVPN; проверить service readiness, разрыв active revoked session, denial нового подключения revoked peer и reconnect non-revoked peer. Связано с Requirement: Effective OpenVPN revocation.
- [ ] 3.6 Добавить проверку missing, unreadable, invalid и expired CRL на серверном пути и документировать observed admission behavior; не объявлять readiness, если revoked credential может вернуться. Связано с Requirement: Effective OpenVPN revocation.

Связано с Requirement: Single-server Make interface.
- [ ] 4.2 Реализовать local interactive revoke: показать выбранный protocol list, принять только exact known device name и до mutation отклонить empty input, EOF, cancellation и unknown name; покрыть все пять путей focused tests. Связано с Requirement: Interactive revocation.
- [ ] 4.3 Связать Make add/export с local authority и publish transaction; проверить, что add создаёт отдельную device identity и развертывает только public enrollment data, а export берёт current endpoint и формирует full-tunnel IPv4/IPv6 routes и DNS `1.1.1.1`, затем `8.8.8.8` для обоих protocol (включая WireGuard profile, не server push) и никогда не получает private key с VPS. Связано с Requirement: Single-server Make interface, Requirement: Private profile handling и vpn-connectivity / Requirement: Server-side full-tunnel support and DNS settings.
